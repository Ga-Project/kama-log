# 窯ログ

自作釉薬のテストピースと窯焼きの条件を記録して、**同じ調合の結果を並べて見比べる**ためのノートです。
記録はすべてお使いの端末のブラウザの中だけに保存されます。アカウント登録は要りません。

陶芸では、同じ調合でも素地・原料・窯・雰囲気（酸化／還元）・棚の位置で焼き上がりが変わります。
そのため「何をどう変えたら、どう出たか」を残しておかないと、良かった焼きを二度と再現できません。
けれど実際の記録は、手帳のメモとスマホの写真と頭の中に散らばりがちです。
窯ログは、その散らばりを1か所にまとめて、**あとから並べて比べられる形**にしておくための道具です。

釉薬の計算（ゼーゲル式など）は持ちません。計算ができる無料のツールは既にたくさんあるので、
このアプリは**記録と比較だけ**に絞っています。

## 誰のためのものか

- 自作釉薬をテストピースで試して、配合を少しずつ変えながら追い込んでいる人
- 電気窯や七輪で焼いていて、温度や雰囲気で結果が変わるのを自分で確かめたい人

## できること

| 機能               | 内容                                                                               |
| ------------------ | ---------------------------------------------------------------------------------- |
| テストピースの記録 | 識別番号・調合名・配合（部数）・所見・結果・写真を残せます                         |
| 窯焼きの記録       | 温度カーブ（経過と温度の点）・酸化／還元の切り替わり・棚の段数・目標温度を残せます |
| 棚位置の記録       | 窯の断面の形で棚を選び、どの段に置いたかを残せます                                 |
| 横断比較           | 同じ配合のテストピースを横一列に並べ、**前回と変わった条件に印**を付けます         |
| 色片だけを並べる   | 表示を発色だけに切り替えて、色の違いだけを見比べられます                           |
| 書き出し           | テストピースと焼成を CSV に書き出せます。印刷（PDF）もできます                     |

書き出しは2つのファイル（テストピース／焼成）に分かれますが、どちらにも「焼成ID」の列があります。
日付・名前・番号が同じ焼成が2回あっても、この列でどちらに紐付いていたかが分かります。
配合の数は保存されている**部数**です（% ではありません）。
配合の列は `材料名 部数` をスラッシュ区切りで並べます。材料名そのものにスラッシュが入っているときは、
バックスラッシュを前に付けて `\/` と書き出します。そのまま出すと、1つの材料名なのか2つの材料なのかが
読めなくなるためです。

すべて無料で、機能に制限はかけていません。

## 使い方

1. **焼成をつくる**（「焼成」→「＋ 焼成を記録」）
   日付と名前を入れ、温度の点を打ちます。経過は `0:00` の形でも、分の数値でも入力できます。
   還元に切り替えた点には「ここから還元」を指定すると、雰囲気の帯が自動で切り替わります。
2. **テストピースを記録する**（「テストピース」）
   識別番号（タイルに書いた番号）と所見だけが必須です。配合・焼成・棚位置・写真は後からでも構いません。
   写真を選ぶと、端末の中で長辺 1024px に縮小してから保存します。
3. **並べて比べる**（「比較」）
   調合を選ぶと、その配合のテストピースが古い順に一列に並びます。
   前の列と値が変わったところには縦の印が付くので、何を変えて結果が変わったのかが分かります。

### うまくいかなかった焼きも残してください

貫入・ピンホール・流れすぎ・剥離といった結果も、良好と同じ見た目のタグとして記録します。
失敗をエラー扱いしないのは意図的です。あとで効くのは、たいてい失敗のほうの記録です。

写真を撮り忘れても、所見だけで保存できます。色だけ覚えているときは「色メモ」で
だいたいの色を置いておけます。

## 制限事項（できないこと）

- **釉薬の計算をしません。** ゼーゲル式、調合の自動補正、温度の予測はありません。
- **焼成結果の再現性を保証しません。** 記録は参考情報です。
- **記録はこの端末の中にしかありません。** 別の端末やブラウザには引き継がれません。
  ブラウザのデータ削除、プライベートウィンドウの終了、端末の空き容量不足、
  ブラウザによる自動削除で消えることがあります。**大切な記録は CSV に書き出して保管してください。**
- 写真は端末の保存領域を使います。空きが少なくなると保存できないことがあります。
  そのときも**記録の本文（所見や配合）は先に保存され、写真だけが付かない状態**になります。
- 複数人での共有・同期はできません。
- ページの閲覧数を数えるために、アクセス解析（Cookie を使わない匿名の集計）へページの表示だけを送っています。
  記録した配合・所見・写真などの内容が送られることはありません。

## 開発

Next.js（App Router）。`out/` への static export で配信するため、サーバランタイムは不要です。

```bash
./setup.sh        # 依存のインストール
pnpm dev          # 開発サーバ
pnpm test         # ユニットテスト（node:test）
pnpm typecheck    # 型チェック
pnpm lint         # Lint
pnpm build        # out/ に static export
./run.sh serve    # out/ をローカル配信して確認
```

サブディレクトリ配信（`<owner>.github.io/kama-log/`）でビルドするときは、
`NEXT_PUBLIC_BASE_PATH=/kama-log` を渡します。

### 構成

| パス                | 役割                                                     |
| ------------------- | -------------------------------------------------------- |
| `lib/model.mjs`     | 記録の定義・採番・配合の正規化（同一調合の判定を含む）   |
| `lib/curve.mjs`     | 温度カーブの要約と描画座標。可視化ライブラリは使いません |
| `lib/compare.mjs`   | 横断比較の列・行の組み立てと差分判定                     |
| `lib/serialize.mjs` | CSV 書き出し                                             |
| `lib/storage.mjs`   | IndexedDB と容量まわり                                   |
| `app/`              | 画面（炉前・焼成・テストピース・比較・書き出し）         |

保存の順序は **「記録本体 → 写真」** に固定しています。逆にすると、空き容量が足りないときに
所見まで失われます。`lib/storage.mjs` を変更するときはこの順序を崩さないでください。
